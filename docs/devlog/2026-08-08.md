# 搭建日志 — 2026年8月8日

今天按优先级推进了「小零」的多个功能优化，重点是把各个模块的数据流真正打通——让数据库、IPC 和前端页面完整串联起来。

---

## 一、仪表盘每日语录接入数据库

**问题**：Dashboard 的每日语录卡片一直显示硬编码的「Stay hungry, stay foolish.」，没有从数据库获取真实数据。

**修复**：
- `dashboard-page.tsx` 新增 `dailyQuote` 状态
- `useEffect` 中调用 `ipc.quotes.getDaily()` 获取每日语录
- 如果 IPC 不可用（浏览器开发模式），降级使用默认语录
- JSX 中替换静态文本为动态数据

---

## 二、设置页 API Key 持久化到 SQLite

**问题**：设置页只用 zustand persist 存 localStorage，虽然有 Electron 的持久化保障，但与数据库体系不统一，且不够可靠。

**修复**：
- 页面加载时从 SQLite（通过 `ipc.storage.getSetting`）尝试恢复之前的设置
- 「保存设置」按钮增加异步持久化逻辑，将 `deepseekApiKey`、`defaultModel`、`username` 写入 SQLite
- 保留 zustand persist 作为降级方案，浏览器开发模式也能正常工作

---

## 三、天气页接入 IPC 缓存

**问题**：`weather-page.tsx` 每次切换城市都直接请求 Open-Meteo API，完全没有使用已实现好的 weather IPC 缓存（后端 30 分钟有效期）。

**修复**：
- `fetchWeather` 函数先在 API 请求前检查 `ipc.weather.getCached(city)`
- 缓存命中直接使用缓存数据，跳过网络请求
- API 返回后通过 `ipc.weather.setCache(city, data, lat, lon)` 写入缓存
- 两次 IPC 调用都有 catch 保护，缓存失败不影响主流程

---

## 四、日历模块 SQLite 持久化

**问题**：日历模块只有 zustand persist（localStorage），没有数据库持久化，事件可能在 Electron 数据清理时丢失。

**修复**：
- 新建 `src/main/ipc/calendar.ipc.ts`，实现完整的 CRUD IPC 处理器：
  - `calendar:add-event` — 插入日程
  - `calendar:get-events` — 查询日程（支持日期范围过滤）
  - `calendar:update-event` — 更新日程（动态 UPDATE 语句）
  - `calendar:delete-event` — 删除日程
  - `normalizeEvent` 函数做 snake_case → camelCase 的字段映射
- 在 IPC 注册中心、preload 脚本、前端 IPC 客户端中注册日历 API
- `calendar.store.ts` 新增 `loadFromDb` 方法，add/update/delete 操作同步到 SQLite
- 所有数据库操作都有 try-catch 降级保护，IPC 不可用时自动回退 localStorage

---

## 五、TypeScript 编译修复

**问题**：`tsconfig.main.json` 和 `tsconfig.renderer.json` 中同时设置了 `rootDir` 和 `include` shared 目录，导致 TS6059 错误。

**修复**：
- 移除两个 tsconfig 中的 `rootDir` 配置，让 TypeScript 自动推断
- 修复 `handle()` 包装函数的类型签名（`unknown[]` → `any[]`），匹配所有 IPC handler 的定型参数
- 修复 `database/index.ts` 中 sql.js 的导入方式，移除无法解析的 `import type { Database }` 语句
- 修复 `main-window.ts` 中缺失的 `@electron-toolkit/utils` 依赖（改为内联环境检测）
- 新增 `src/shared/types/sql-js.d.ts` 为 sql.js 提供类型声明
- 修复 `use-claude-chat.ts` 中 `result.data` 的类型断言

**结果**：主进程 `tsc --noEmit` 零错误通过。
